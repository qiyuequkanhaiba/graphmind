# 图谱路径探索与 AI 解释设计规格

## 背景

GraphMind 已经具备中文专业工作台、表格导入、关系推断、证据检查、关系审核、AI 问答、图谱节点拖拽、关系强度筛选和专业节点摘要。当前中心图谱已经从普通连线展示升级为“关系分析”视图。下一步应提升“理解关系”的能力，让用户不仅能看到节点和边，还能快速回答：

- 这个表和哪些表最相关？
- 这个字段的上游和下游是什么？
- 两个节点之间有没有可解释路径？
- AI 为什么认为这条关系成立？

## 目标

1. 在图谱中新增路径探索能力，支持围绕当前选中节点查看一跳、两跳邻域。
2. 让图谱高亮从“AI 答案路径”扩展为“用户主动探索路径”。
3. 在右侧洞察区新增路径摘要，让用户不用离开图谱就能理解上下游关系。
4. 增加 AI 解释快捷入口，基于当前选中项生成带证据的中文问题。
5. 保持当前 GitNexus 式均衡工作台布局，不引入新的复杂页面。

## 非目标

1. 本轮不引入 3D 图谱。3D 作为后续实验视图。
2. 本轮不接入外部大模型服务，继续复用当前后端可追溯回答能力。
3. 本轮不做跨数据集全局路径搜索。
4. 本轮不持久化用户探索路径。
5. 本轮不重写关系推断算法。

## 用户体验

用户点击任意表、字段或维度节点后：

- 图谱中该节点保持选中态。
- 工具条出现或启用路径探索控制。
- 用户可切换“邻域：一跳 / 两跳”。
- 与当前节点相关的路径高亮，其余节点和边弱化。
- 右侧证据或洞察区显示路径摘要：
  - 上游节点数量
  - 下游节点数量
  - 相关关系类型
  - 待审核关系数量
- 用户可点击“解释当前节点”或“解释当前关系”，自动向 AI 问答发送带上下文的问题。

如果用户选中的是关系边：

- 图谱高亮源节点、目标节点和该关系。
- 路径摘要显示关系类型、置信度、状态和证据引用。
- AI 快捷入口生成“解释这条关系为什么成立”的问题。

## 前端设计

### 路径状态

在 `Workspace` 中新增本地探索状态：

- `explorationMode`: `off | one_hop | two_hop`
- `explorationPath`: `number[]`

`explorationPath` 与现有 `highlightedGraphPath` 合并后传入 `GraphCanvas`、`EvidenceInspector`、`WorkbenchStatusBar`。

合并规则：

1. AI 返回的 `highlightedGraphPath` 继续保留。
2. 用户主动探索路径优先级更高。
3. 如果用户关闭路径探索，则只显示 AI 路径。

### 路径计算

新增纯前端 helper，例如 `graphPathInsights.ts`：

- `getNodeNeighborhood(graph, nodeId, depth)`
- `getRelationshipPathSummary(graph, selection, depth)`
- `mergeHighlightedPaths(aiPath, explorationPath)`

一跳邻域：

- 当前节点
- 与当前节点直接相连的边
- 直接相邻节点

两跳邻域：

- 一跳结果
- 从一跳相邻节点继续扩展一次
- 默认限制结果数量，避免大图谱里高亮过多

边的高亮策略：

- 当前 `highlightedGraphPath` 仍然使用节点 id。
- 新增或扩展边高亮 class 需要兼容现有测试。
- 如果短期不改数据结构，可先高亮路径中的节点，并通过选中边保留关系视觉。

### 图谱控制

在 `GraphCanvas` 工具条增加路径控制：

- `邻域`
- `关闭`
- `一跳`
- `两跳`

控制只在有选中节点时启用。没有选中节点时按钮 disabled。

### 右侧洞察

在 `EvidenceInspector` 或 `InsightPanel` 中增加路径摘要区域。

推荐先放在 `EvidenceInspector`：

- 选中节点时，显示“路径摘要”
- 展示上游、下游、关系类型、待审核数
- 保留原有元数据和相邻关系数量

这样可以避免新增右侧 tab，也更符合当前工作台结构。

### AI 快捷解释

在 `ChatPanel` 或 `EvidenceInspector` 中增加快捷按钮：

- 选中节点：`解释当前节点关系`
- 选中关系：`解释当前关系证据`
- 无选择：不显示或 disabled

点击后调用现有 `onAsk(question, selectionContext)`：

- 节点问题示例：`解释当前选中节点的上下游关系，并说明证据来源。`
- 关系问题示例：`解释当前选中关系为什么可能成立，并说明置信度和证据。`

后端已有选中节点解释能力。本轮需要补齐选中关系解释：

- 当 selection.kind 为 `edge` 时，返回源节点、目标节点、关系类型、置信度、状态、证据摘要。
- citations 指向关系证据引用或 suggestion。
- highlighted_graph_path 包含源节点和目标节点。

## 后端设计

扩展 `ChatService._selected_item_relationship_answer`：

- 当前只支持 `selection.kind == "node"`。
- 新增 `edge` 分支。
- 查询 `GraphEdge` 和两端 `GraphNode`。
- 生成中文优先的可追溯回答。

回答应包含：

- 关系方向
- 关系类型
- 置信度
- 审核状态
- 证据摘要

错误处理：

- 找不到边：返回低置信度回答。
- 找不到两端节点：仍返回边信息，但标记节点缺失。
- 证据为空：说明这是结构关系或暂无详细证据。

## 数据流

1. 用户点击图谱节点或边。
2. `Workspace.selection` 更新。
3. 用户开启一跳或两跳探索。
4. 前端 helper 从 `graph.nodes` 和 `graph.edges` 计算路径节点。
5. `GraphCanvas` 接收合并后的高亮路径。
6. `EvidenceInspector` 显示路径摘要。
7. 用户点击 AI 解释按钮。
8. `Workspace` 将问题和 selection context 传给 `onAsk`。
9. 后端返回回答、引用和高亮路径。
10. 前端聊天区展示回答，图谱继续高亮相关节点。

## 测试计划

前端测试：

- 路径 helper 能计算一跳邻域。
- 路径 helper 能计算两跳邻域并去重。
- 选中节点后一跳按钮可用。
- 开启一跳后相关节点高亮。
- 路径摘要显示上游、下游和待审核数量。
- AI 快捷解释按钮用当前 selection 调用 `onAsk`。

后端测试：

- 选中节点解释保持现有行为。
- 选中关系解释返回源、目标、置信度和证据摘要。
- 找不到关系时返回低置信度回答。

验证：

- `npm test`
- `npm run lint`
- `npm run build`
- 后端 `pytest`
- 浏览器检查：选择节点、切换一跳/两跳、触发 AI 解释。

## 验收标准

1. 用户选中节点后可以启用一跳和两跳路径探索。
2. 图谱能高亮邻域路径，关闭探索后恢复普通视图。
3. 右侧能显示当前选中节点的路径摘要。
4. 用户可以一键让 AI 解释当前节点或关系。
5. 选中关系的 AI 解释包含关系类型、置信度和证据。
6. 所有前端和后端测试通过。

## 后续方向

完成本轮后，再进入 3D 图谱实验视图：

- 保留 2D 为默认专业分析视图。
- 新增 `2D / 3D` 视图切换。
- 3D 只用于复杂网络探索，不替代审核和证据工作流。
